## Spacing & Layout System

### Touch Target Sizing (Requirement U1)

**Button wrapper (hit area):**
- 44×44px minimum (WCAG 2.5.5 AAA)
- Tailwind class: `w-11 h-11` (2.75rem = 44px)
- Flexbox centered: `flex items-center justify-center`
- SVG or icon: 14–18px (stays small; padding creates hit area, not visual inflation)

**Applied to:**
- Complete button (task-card)
- Edit button (task-card)
- Delete button (task-card)
- Subtask toggles (task-card)
- Toast dismiss button (toaster)

**Example CSS class chain:**
```
w-11 h-11 flex items-center justify-center rounded-lg 
text-[var(--color-border)] hover:text-[var(--color-accent)] 
transition-colors
```

**Spacing between touch targets:** Minimum `gap-3` (12px) in button groups to exceed 8px minimum.

### Mobile Viewport (Requirement U7)

- **Fix:** Change `min-h-[calc(100vh-52px)]` to `min-h-dvh` in `src/app/tasks/tasks-page-client.tsx:141`
- **Rationale:** `100dvh` (dynamic viewport height) adapts as mobile browser chrome appears/disappears; `100vh` includes hidden address bar and causes content to overflow
- **Fallback:** None; `100dvh` is Baseline Widely Available since June 2025
- **Layout padding clarification:** Planner to decide: remove `-m-6` from page (Option A, simpler) or remove `p-6` from layout (Option B). Recommendation: Option A — consistent 24px gutters everywhere.

### Focus Indicator (Requirement U2)

**Global `:focus-visible` rule (add to `src/app/globals.css`):**

```css
button:focus-visible,
a:focus-visible,
input:focus-visible,
select:focus-visible,
textarea:focus-visible,
[tabindex]:focus-visible {
  outline: 2px solid var(--color-focus);
  outline-offset: 2px;
}
```

**Add to @theme block:**

```css
@theme {
  --color-focus: #7C5CBF;  /* Same as accent purple */
  /* ...existing tokens... */
}
```

**Why global rule:**
- One rule applies everywhere; no component can be forgotten
- `outline` doesn't consume layout space (no jumping when focused)
- `outline-offset: 2px` provides breathing room
- `:focus-visible` only shows for keyboard/assistive tech, not mouse

**Local opt-outs (only if ring clips):** Add component-level override:
```css
.my-button:focus-visible {
  outline: none;
  /* Provide alternative: box-shadow, border, or other styling */
}
```

## Component Specifications

### Dialog Primitive (Requirement U3)

**New component:** `src/components/dialog.tsx` wrapping native `<dialog>` element

**Behavior:**
- Browser provides: focus trap, Escape-to-close, inert background, top-layer stacking, focus restoration
- Component provides: React open/close lifecycle, initial focus selector, accessibility attributes
- Three callers: `new-task-modal.tsx`, `edit-task-modal.tsx`, delete confirm dialog

**HTML structure:**
```html
<dialog
  role="dialog"
  aria-modal="true"
  aria-labelledby="modal-title"
>
  <!-- Modal content -->
</dialog>
```

**Initial focus:**
- Task modals: First `<input type="text">` (title field) — users open to type
- Delete confirm: Cancel button — destructive action must not be one Enter keystroke away

**Styling:**
- `rounded-[14px]` (matches existing card radius)
- `border border-[var(--color-border)]` (light purple)
- `bg-[var(--color-surface)]` (white)
- `shadow-xl` (same as login card: `box-shadow: 0 8px 32px rgba(124,92,191,0.14), 0 2px 8px rgba(0,0,0,0.06)`)
- `max-w-md` (448px; fits 375px phones with gutters)
- `max-h-[90vh]` (scrollable on small screens)
- Backdrop: `backdrop:bg-black/40` (browser-provided via CSS, inert when dialog is open)

**Focus restoration:** Browser automatic; verify in tests with manual keyboard pass.

### Live Regions for Toast Announcements (Requirement U4)

**Convert single toast container to two regions:**

**Region 1 (Success & Warning):**
```html
<div
  role="status"
  aria-live="polite"
  aria-atomic="true"
  className="fixed bottom-4 right-4 z-50 flex flex-col gap-2"
>
  <!-- Success/warning toasts render here -->
</div>
```

**Region 2 (Errors only):**
```html
<div
  role="alert"
  aria-live="assertive"
  aria-atomic="true"
  className="fixed bottom-4 right-4 z-50 flex flex-col gap-2"
>
  <!-- Error toasts render here -->
</div>
```

**Key differences:**
- `role="status"` + `aria-live="polite"` (waits for screen reader to finish current speech)
- `role="alert"` + `aria-live="assertive"` (interrupts to announce critical errors)
- Regions **must be mounted at page load** (empty initially); screen readers hook them on load

**Auto-dismiss timing:**
- Success: 3500ms (below WCAG 2.2.1 threshold for content user must read)
- Warning: 3500ms
- Error: **NO auto-dismiss** (user must explicitly close; errors worth re-reading)

**Dismiss button per toast:**
- Size: 44×44px (`w-11 h-11`)
- Icon: `✕` (U+2715, multiplication sign)
- aria-label: `Close ${type} message` (e.g., "Close error message")
- Hover: `hover:bg-white/20` (subtle lightening)

**Toast card styling:**
- Success: `bg-gray-900` (dark) + `text-white`
- Warning: `bg-amber-500` (existing) + `text-white`
- Error: `bg-red-600` (existing) + `text-white`
- Padding: `px-4 py-3` (16px horizontal, 12px vertical)
- Radius: `rounded-lg` (8px)
- Shadow: `shadow-lg` (elevation effect)
- Max width: `max-w-xs` (320px)
- Transition: `transition-all` (smooth fade/slide)

### Task Card Button Labeling (Requirement U1 + Accessibility)

**Update aria-labels to be task-scoped:**

| Button | Current Label | Phase 4 Label |
|--------|---------------|---------------|
| Complete | "Mark complete" | `Mark "${title}" complete` |
| Edit | "Edit task" | `Edit "${title}"` |
| Delete | "Delete task" | `Delete "${title}"` |
| Subtask toggle | "Toggle subtask" | `Mark "${subtask_title}" complete` |

**Rationale:** Screen readers in list-navigation mode read only the label. Without the task title, a user hears "Mark complete" repeated 20 times. With title, each label is unique and contextual.

**Implementation:**
```typescript
aria-label={`Mark "${title}" complete`}
```

### Navigation Cleanup (Requirement U5)

**Delete dead nav pills:**
- Remove `<button>` elements for "All / Household / Work" from `src/app/layout.tsx:44-54`
- These are handler-less duplicates of the real filter controls in `tab-pill.tsx`
- A button that looks interactive and does nothing is worse than no button; pollutes tab order

**Hide nav when signed out:**
- `layout.tsx` already awaits `getUser()` (server component pattern)
- Conditionally render nav links: `{user && <nav>...</nav>}`
- Rationale: No task list for signed-out users; empty nav is confusing

**Not in scope:** `/tasks` signed-out redirect or middleware (auth routing, separate phase)

## Keyboard Navigation Expected Behavior

**Tab order (global):**
1. Nav links (if visible / signed in)
2. Task filter pills (`tab-pill.tsx`)
3. Task cards: complete → edit → delete → subtask toggles (per card)
4. Modals (when open; Tab cycles within modal only)
5. Toast dismiss buttons (only if toast is present)

**Escape key:**
- Closes any open modal (Dialog component handles via browser native)
- **Does NOT** dismiss toasts (users must click dismiss; errors may need re-reading)

**Focus indicator visibility:**
- Should be visible on all above via global `:focus-visible` rule (no per-component configuration needed)

## Implementation Notes

### Preserving Optimistic Close Behavior

Phase 2 decision (D-02 in 02-CONTEXT.md) locked: task modals close optimistically before the server resolves, then roll back if the action fails. Dialog conversion must preserve this: modal closes when user clicks "Add task", toast fires BEFORE `startTransition` settles. Verify in tests: open modal → submit → modal closes immediately → page updates → if error, toast appears (no modal re-open needed).

### No Radix or Component Library

This phase uses only native HTML (`<dialog>`, `aria-live`) and React. No Radix Dialog, no headless UI library. Rationale: one primitive (dialog) is not worth a dependency; native `<dialog>` is mature, well-tested, and provides all needed behavior (focus trap, Escape, inert, top-layer, focus restore).

### jest-axe Coverage

jest-axe finds accessibility violations in unit tests. Run on every component that touches U1–U4 (touch targets, focus, dialogs, live regions). Not a replacement for manual VoiceOver testing; jsdom gaps require manual keyboard pass.
