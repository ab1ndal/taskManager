<objective>
Convert both task modals from their hand-rolled fixed-overlay `<div>` pattern to the `Dialog`
primitive built in 04-01, per CONTEXT.md D-05/D-06/D-07. This is the first of two Wave 2 plans that
depend on Dialog existing; it does not touch `task-card.tsx` or the delete confirm dialog (04-05),
so the two Wave 2 plans have zero file overlap and can run in parallel.

Purpose: Both modals currently render `<div className="fixed inset-0 z-50 ...">` with no
`role="dialog"`, no focus trap, and a hand-rolled backdrop click-to-close. Converting to `Dialog`
gives native focus trap, Escape-to-close, and focus restoration for free while preserving every
existing behavior locked in Phase 2 (optimistic close timing differs between the two modals and
must not change).
Output: Both modals render through `<Dialog>`; their existing test suites still pass, extended with
Escape and initial-focus assertions.
</objective>

<interfaces>
From src/components/dialog.tsx (built in 04-01):
`Dialog({ open, onClose, initialFocusSelector?, ariaLabelledBy?, className?, children })` — a
client component rendering a single `<dialog>` element. Callers must keep their own
`if (!open) return null;` guard before returning `<Dialog>...</Dialog>`, since Dialog's effect
that calls `showModal()` runs once on mount and expects to already be the open instance. Default
`className` already supplies `rounded-[14px] border border-[var(--color-border)]
bg-[var(--color-surface)] shadow-xl p-6 w-full max-w-md max-h-[90vh] overflow-y-auto
backdrop:bg-black/40` — do not re-wrap Dialog's children in another styled div for the outer box;
render the modal's heading and `<form>` directly as Dialog's children.
</interfaces>
