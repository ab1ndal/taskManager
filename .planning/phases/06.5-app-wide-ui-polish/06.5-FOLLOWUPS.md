### F14 — Production's migration history breaks the deploy workflow — CLOSED, PREMISE WAS WRONG (2026-07-27)

Raised from L9, which recorded production's history as holding a single row and was last updated
2026-07-25. It was stale. `supabase migration list --linked` against production, run as the first
step of the repair workflow, showed 001-009 already present: the history had been completed between
then and now, and `deploy-migrations.yml` was never broken.

The repair ran anyway — `migration repair` writes to the history table only and is idempotent, so it
re-asserted 001-009 as applied and dropped the orphaned `20260725220330` row that matched no local
file. `supabase db push --dry-run` then reported "Remote database is up to date", which is the
evidence the deploy path works. Run
[30283909805](https://github.com/ab1ndal/taskManager/actions/runs/30283909805).

Kept from the work: `.github/workflows/repair-migration-history.yml`, manual and gated on typing
REPAIR, for the next time a migration is applied out-of-band; and a `migration list --linked` step in
`deploy-migrations.yml`, so a real mismatch shows up as a readable log line instead of a failed
`create table`.

**The actual lesson** is in L9: a lesson describing a broken state has to be re-verified before it is
acted on. One command would have shown the premise was false.

## Correctness and consistency

### F3 — Subtask delete has no confirmation — CLOSED (`09b6dda`)

The subtask trash button routes through `DeleteConfirmDialog`, the same shell task delete uses. The
confirmation is a second `showModal()` nested inside the open edit modal: it stacks above it in the
top layer, so Escape dismisses only the confirmation. Covered by three tests in
`src/app/tasks/edit-task-modal.test.tsx`.

### F4 — `RowMenu` has no arrow-key navigation — CLOSED (`bed3fa8`)

Implemented rather than dropped: roving focus per the ARIA APG menu-button pattern. The menu is a
single tab stop, Up/Down wrap, Home/End jump to the ends, ArrowUp on the trigger opens with the last
item focused, and Tab leaves the menu. Escape, outside-click dismissal and focus-return to the
trigger are unchanged. Covered by `src/components/__tests__/row-menu.test.tsx` (7 tests).

### F5 — Subtask fields are asymmetric between the two modals — CLOSED (`d5cc3eb`)

The edit modal's add-subtask row now carries title, details and due date, matching the new-task
modal. Existing subtasks render their details and due date, and a pencil opens them for editing
through a new `updateSubtask` action — it edits only the three fields the subtask UI owns and leaves
assignment alone, since a subtask inherits its assignees from its parent. The subtasks query and
`RawTask` now carry `description` and `due_at`.

### F6 — Reopening a parent leaves its subtasks completed — OPEN

Deliberate, documented in `actions.ts` and covered by a unit test: the subtask work was genuinely
done, and whatever reopened the parent is new work. Worth watching in real use — reopening "take the
bins out" leaves both its subtasks ticked, which may read as wrong to someone who expected a reset.

**Done:** confirmed in use, or changed with a stated reason. Not a bug today.

## Verification gaps the new suite does not close

### F7 — Drag-to-reorder has zero end-to-end coverage — CLOSED (`e752d88`)

`e2e/drag-reorder.spec.ts` covers the pointer path (mouse on desktop; a dispatched touch sequence
past the library's 120ms long-press threshold on the iPhone profile, since Playwright's touchscreen
API exposes taps only) and the keyboard path (focus handle, Space, Arrow, Space). Each asserts the
new order survives a reload, and each restores the seeded order before it ends. Passing in chromium,
webkit, firefox and iphone.

### F8 — Contrast and dark mode are measured on `/tasks` only — CLOSED (`d95fb70`)

The walk is parameterised over `/tasks`, `/workspaces`, `/profile`, `/login` (in a signed-out
context — the proxy redirects a signed-in user away from it), the new-task and edit-task dialogs and
the delete confirmation, in both schemes.

It immediately caught a real failure: `--color-text-muted` was 4.39:1 on `--color-surface-sunken`,
the panel behind the Updates and Subtasks sections, while clearing 4.5:1 on the other two light
surfaces. Darkened `#726f80` → `#6d6a7b` (4.73:1 on the sunken surface), still lighter than
`--color-text-secondary`, so the hierarchy is unchanged. Dark mode was already at 6.05:1.

### F9 — No screenshot baselines — CLOSED (`ceff361`)

Baselines for the task list, both dialogs (including the edit dialog scrolled to the Subtasks panel,
which sits below the fold), and the workspace card, in both schemes on chromium and the iPhone
profile. Update timestamps are masked. Firefox and WebKit are excluded on purpose — a third and
fourth set of baselines is maintenance without new signal, and the property-based specs already run
in all four engines.

Baselines are platform-suffixed, so a machine with different font rendering regenerates rather than
inherits: `npx playwright test screenshots --update-snapshots`.

### F10 — Dictation and microphone-permission denial still need a human — OPEN

cloud service in Chrome and absent in Firefox — so `06-VERIFICATION.md`'s dictation checks cannot be
automated with this harness.

app shell. If "local distribution" is meant to survive a plane or a lift, that is real work — a
service worker with a precached shell and a considered stale-while-revalidate policy for task data,
plus a story for writes made offline.
