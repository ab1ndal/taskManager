# Phase 6.5 — App-Wide UI/UX Audit

Date: 2026-07-26. Scope: every rendered surface in `src/` on
`worktree-phase-06-task-updates-speech-subtasks` (phase 06 code included, since it is part of what
6.5 must polish). Method: `ui-ux-pro-max` rule matrix (accessibility → touch → style → layout →
type/color → motion → forms → nav) plus the `taste-skill` audit-first pass for AI-default tells.

Design read: **internal productivity tool for two workspace kinds, warm off-white + single purple
accent, calm/minimal language.** The existing accent (`#7C5CBF`) is brand, not AI-purple drift, so
it stays; the LILA-rule override applies.

Findings are ordered by user-visible impact. Each is a concrete, fixable change.

---

## P0 — structurally broken

**1. Every `/tasks` render is taller than the viewport, and there are two `<main>` landmarks.**
`layout.tsx:53` wraps children in `<main className="p-6">`. `tasks-page-client.tsx:234` then opens
`<div className="flex min-h-dvh">` containing a second `<main className="flex-1 p-6">` (line 310).
Result: 52px nav + 24px padding + a full-`dvh` block + 24px padding, so the page always scrolls even
with zero tasks, the sidebar is cut off at the bottom, and content carries 48px of padding on the
left. Screen readers see two `main` regions.
Fix: drop the padding from the root `<main>` (or make it route-aware), make the inner element a
`<div>`, and size the shell `min-h-[calc(100dvh-52px)]`.

**2. The workspaces create-modal is a hand-rolled overlay, not the shared `Dialog`.**
`workspaces-client.tsx:80-91` builds a `fixed inset-0` div with a click-outside handler. No
`role="dialog"`, no `aria-modal`, no focus trap, no Escape-to-close, no focus restore — every
guarantee Phase 04 added to `components/dialog.tsx`. It is also the only 12px-radius surface in the
app and uses `--shadow-login` on a non-login card.
Fix: render it through `Dialog`.

**3. Emoji used as UI icons.** ✅ **Fixed 2026-07-26** — `🎤` / `●` on the dictation button, `✕` on
toast close and on subtask remove are now `Mic` / `Square` / `X` from `lucide-react`. The dictation
button also gains a red border and a filled stop square while listening, so the recording state is
carried by more than an `aria-label`. Still open for the full 6.5 pass: a text "Listening" cue.

**4. Error toasts never dismiss and can collide.** `toaster.tsx:38` schedules the 3.5s removal only
for polite toasts; `assertiveToasts` are removed by the close button alone, so errors stack forever.
`const id = Date.now()` (line 32) also duplicates React keys when two toasts fire in the same
millisecond.
Fix: auto-dismiss errors on a longer timer (8-10s) or cap the stack; key with `crypto.randomUUID()`.

**5. Empty state lies under a filter.** `tasks-page-client.tsx:184` computes `hasAnyTasks` from the
*filtered* list, so "Shared" or a workspace tab with no matches renders `EmptyState`'s "No tasks
yet. Add one to get started." The user has tasks; they filtered them away.
Fix: separate no-tasks-at-all from no-results-for-this-filter, with a "Clear filter" action.

**6. The edit modal mixes transactional and immediate saves.** Title/description/due/assignees are
staged behind Save/Cancel, but Updates (`edit-task-modal.tsx:82`) and Subtasks (line 117) write to
the server the moment their button is pressed. Cancel does not undo them. Nothing in the UI
signals the difference.
Fix: either move the two sections outside the form's visual container with their own framing, or
stage them too.

## P1 — design system incoherence (blocks dark mode, which is now a 6.5 criterion)

**7. Radius tokens exist and are never used.** `globals.css:26-28` defines `--radius-sm/md/lg`
(8/12/16). Shipped code uses literal `rounded-[8px]`, `rounded-[11px]` (`task-card.tsx:68`),
`rounded-[12px]`, `rounded-[14px]` (`dialog.tsx:50`), `rounded-[16px]`, and `rounded-full` —
six scales, none tokenised.
Fix: pick three, map to the tokens, replace every literal.

**8. Three different focus treatments.** `globals.css:35` sets a global 2px outline on
`:focus-visible`; modal inputs override it with `focus:outline-none focus:ring-1`; login and profile
inputs use `focus:border-accent focus:ring-[3px] ring-accent/10`; the workspaces modal uses
`focus:ring-2 focus:border-transparent`. The same keyboard action looks different on three screens.

**9. Raw palette classes bypass the token layer.** `bg-red-50 / text-red-600` (every inline form
error, five files), `bg-amber-50`, `bg-emerald-50` (`task-card.tsx:11-13`), `bg-gray-900 /
bg-red-600 / bg-amber-500` (`toaster.tsx:21`), `bg-indigo-100 / bg-sky-100 / bg-green-100 /
bg-red-100` (`workspace-card.tsx:60,90`). Each one is a surface that dark mode cannot reach.
Fix: semantic tokens — `--color-danger-surface`, `--color-danger-text`, `--color-warning-*`,
`--color-success-*`, `--color-kind-household`, `--color-kind-work`.

**10. Fifteen hand-rolled inline SVGs, no icon library.** ✅ **Fixed 2026-07-26.** Was: sizes 10,
12, 14, 15, 18, 64 and stroke widths 1.5, 1.6, 1.8, 2, with two sibling buttons on the same task row
at 18px and 14px.

Now `lucide-react` throughout, with `src/components/icon.tsx` holding the only three numbers:
`ICON_PRIMARY = 20` (leading control of a row, standalone action), `ICON_SECONDARY = 16`
(supporting controls, anything inline with text), `ICON_STROKE = 1.75`. The 20/16 split on a task
row is now a stated hierarchy — complete and drag are primary, edit and delete are secondary —
rather than the accident it was.

The one surviving inline SVG is `EmptyState`'s 64px illustration in `task-card.tsx`. That is
artwork, not an icon; swapping it for a lucide glyph would lose the drawing.

**Decision (user, 2026-07-26): `lucide-react` is the app's icon library.** Chosen for a clean,
neutral interface that matches the existing calm/minimal language. Do not introduce a second icon
family.

**11. Type scale is ad-hoc and dips below the readable minimum.** `text-[10px]` section labels,
`text-[11px]` for deadline badges, shared badges, workspace name and member counts — that is the
task card's entire metadata line rendered below 12px. Nav links are `text-xs` (12px) for primary
navigation.
Fix: a 12/14/16/20/24 scale; metadata at 12px minimum, nav at 14px.

**12. No dark mode and no reduced-motion guard.** One `@theme` block, no
`prefers-color-scheme`; `modal-in` (`globals.css:3`) and every `transition-*` run unconditionally.

## P2 — interaction and content

**13. Four always-on 44px buttons per task row.** Drag handle, complete, edit, delete
(`task-card.tsx:73-146`) sit at full muted colour on every row. At 375px they consume ~176px, so the
title gets roughly half the row and truncates early; visually, four grey glyphs compete with the
task title for attention.
Fix: keep complete + drag always visible, reveal edit/delete on hover and focus-within at `md+`,
collapse to an overflow menu on touch.

**14. Subtask rows are indented by a 44px button plus `ml-7`.** `task-card.tsx:161-182` pairs a
14px circle inside a 44px hit target with `text-xs` text, so each subtask is a 44px-tall row with a
tiny mark floating in it, roughly 72px from the card edge.

**15. New-task subtask rows are unusable on mobile.** `new-task-modal.tsx:270-308` puts title,
description, date and remove in one flex row inside a `max-w-md` dialog. Under 640px each field is
about 60px wide.
Fix: stack per row below `sm`, or move description/date behind a per-row disclosure.

**16. Destructive workspace leave is hover-only and unconfirmed.** `workspace-card.tsx:88-92`
swaps the "Joined" label to "Leave" on `mouseenter`. Touch users get no such hint, and the action
fires with no confirmation, unlike task delete which has a whole dialog.

**17. Top nav has no active state.** `layout.tsx:37-42` renders Tasks and Workspaces identically
regardless of route, while the sidebar (`tasks-page-client.tsx:113-121`) does highlight. Sign out
also sits inline with the profile link with no separation.

**18. Updates list has no empty state, no scroll affordance, and absolute timestamps.**
`edit-task-modal.tsx:273-283`: `max-h-40 overflow-y-auto`, newest appended at the bottom, no
auto-scroll on add, and `new Date(u.createdAt).toLocaleString()` renders a full locale timestamp per
row. Subtasks list (line 330) likewise has no empty state and its items are not toggleable, though
they are on the task card.

**19. Double-reported errors on workspace create.** `workspaces-client.tsx:33-34` sets `formError`
*and* fires an error toast for the same failure. The task modals deliberately do inline-only.

**20. Dead animation code.** `workspaces-client.tsx:67` sets a staggered `animationDelay` and
`workspace-card.tsx:66` sets `animationFillMode`, but no animation is ever declared.

**21. Small correctness nits.** `dialog.tsx:50` and `delete-confirm-dialog.tsx:26` use `max-h-[90vh]`
(should be `dvh`); `login-card.tsx:110` uses `min-h-[80vh]`; the completed-section toggle
(`completed-section.tsx:24`) has no `aria-expanded`; `/profile` has no `loading.tsx` and falls back
to a bare "Loading…" string while every other route has a skeleton.

## Not found (things that are already right)

Touch targets are 44px throughout, `aria-label`s are present on every icon-only button, the toaster
has correct polite/assertive live regions, `/tasks` has both `loading.tsx` and `error.tsx`, inline
form errors carry `role="alert"`, and the drag handle keeps a keyboard path. Phase 04 did its job;
what is left is visual system work, not accessibility rescue.
