# Phase 6.5 — App-Wide UI/UX Audit

Date: 2026-07-26. Scope: every rendered surface in `src/` on
`worktree-phase-06-task-updates-speech-subtasks` (phase 06 code included, since it is part of what
6.5 must polish). Method: `ui-ux-pro-max` rule matrix (accessibility → touch → style → layout →
type/color → motion → forms → nav) plus the `taste-skill` audit-first pass for AI-default tells.

Design read: **internal productivity tool for two workspace kinds, warm off-white + single purple
accent, calm/minimal language.** The existing accent (`#7C5CBF`) is brand, not AI-purple drift, so
it stays; the LILA-rule override applies.

Findings are ordered by user-visible impact. Each is a concrete, fixable change.

---

## P0 — structurally broken

**1. Every `/tasks` render is taller than the viewport, and there are two `<main>` landmarks.** ✅ **Fixed 2026-07-26.** The root layout no longer wraps children in `<main>`; each route renders its own, so there is one landmark per document and the padding belongs to the page that wants it. The tasks shell is `calc(100dvh - var(--nav-height))`.

**2. The workspaces create-modal is a hand-rolled overlay, not the shared `Dialog`.** ✅ **Fixed 2026-07-26.** Now renders through `Dialog`, so it inherits the native `<dialog>.showModal()` behaviour: focus trap, Escape, focus restore, `aria-modal`. Its inline error also referenced `--color-deadline-red`, deleted by the token pass — the var resolved to nothing and the message rendered in the inherited colour.

**3. Emoji used as UI icons.** ✅ **Fixed 2026-07-26** — `🎤` / `●` on the dictation button, `✕` on
toast close and on subtask remove are now `Mic` / `Square` / `X` from `lucide-react`. The dictation
button also gains a red border and a filled stop square while listening, so the recording state is
carried by more than an `aria-label`. Still open for the full 6.5 pass: a text "Listening" cue.

**4. Error toasts never dismiss and can collide.** ✅ **Fixed 2026-07-26.** Errors last 10s and warnings 6s against a success's 3.5s; each lane caps at three; ids are `crypto.randomUUID()`; timers clear on unmount.

**5. Empty state lies under a filter.** ✅ **Fixed 2026-07-26.** Filtered-empty is its own variant saying the other tasks are still there, with a "Show all tasks" action.

**6. The edit modal mixes transactional and immediate saves.** ✅ **Fixed 2026-07-26.** Updates and Subtasks sit on the sunken surface with explicit "Posts immediately" / "Saves immediately" notes, so Cancel no longer looks like it would undo them.

## P1 — design system incoherence (blocks dark mode, which is now a 6.5 criterion)

**7. Radius tokens exist and are never used.** ✅ **Fixed 2026-07-26 (token pass).** Was eight
literal radii. Now three, with a stated rule: `rounded-sm` (8px) for controls — inputs, buttons,
badges, toasts; `rounded-md` (12px) for cards and grouped containers; `rounded-lg` (16px) for
dialogs and the login card. `rounded-full` still marks pills, which is a shape, not a scale step.

**8. Three different focus treatments.** ✅ **Fixed 2026-07-26 (token pass).** Every per-component
`focus:ring-*` / `focus:outline-none` override is gone; the global `:focus-visible` outline in
`globals.css` is now the only one. Components must not reintroduce their own.

**9. Raw palette classes bypass the token layer.** ✅ **Fixed 2026-07-26 (token pass).** Zero raw
palette classes remain in `src/` — verified by grep for
`(bg|text|border)-(red|amber|emerald|green|indigo|sky|gray|white|black)`.

The token set that replaced them: `--color-danger-{surface,text,border,solid,solid-hover}`,
`--color-warning-{surface,text,solid}`, `--color-success-{surface,text}`,
`--color-kind-{household,work}-{surface,text}`, `--color-inverse-{surface,text}`,
`--color-text-on-accent`, `--color-text-on-solid`, `--color-scrim`, `--color-surface-sunken`.

Two colour bugs surfaced while doing it, both now fixed:
- The deadline badges were failing AA. `#D4A017` on `amber-50` measured 2.3:1 and `#4A9B6F` on
  `emerald-50` measured 3.1:1, at 11px. The status tokens that replaced them are 5.7:1 and 6.2:1.
- `--color-text-muted` was `#A09CB0`, then briefly `#83808f`, both below AA on white (3.7:1 and
  3.85:1) despite carrying real text — workspace names, member counts, dates. Now `#726f80` light
  (4.88:1) and `#9591a6` dark (5.44:1).

Contrast for all 14 semantic pairs was computed in both themes; every one clears 4.5:1. That
check is arithmetic on the token values, not a rendered-page audit — see the caveat below.

**10. Fifteen hand-rolled inline SVGs, no icon library.** ✅ **Fixed 2026-07-26.** Was: sizes 10,
12, 14, 15, 18, 64 and stroke widths 1.5, 1.6, 1.8, 2, with two sibling buttons on the same task row
at 18px and 14px.

Now `lucide-react` throughout, with `src/components/icon.tsx` holding the only three numbers:
`ICON_PRIMARY = 20` (leading control of a row, standalone action), `ICON_SECONDARY = 16`
(supporting controls, anything inline with text), `ICON_STROKE = 1.75`. The 20/16 split on a task
row is now a stated hierarchy — complete and drag are primary, edit and delete are secondary —
rather than the accident it was.

The one surviving inline SVG is `EmptyState`'s 64px illustration in `task-card.tsx`. That is
artwork, not an icon; swapping it for a lucide glyph would lose the drawing.

**Decision (user, 2026-07-26): `lucide-react` is the app's icon library.** Chosen for a clean,
neutral interface that matches the existing calm/minimal language. Do not introduce a second icon
family.

**11. Type scale is ad-hoc and dips below the readable minimum.** ✅ **Mostly fixed 2026-07-26
(token pass).** No `text-[10px]` or `text-[11px]` literals remain. Body-adjacent copy — workspace
names, member counts — moved up to `text-xs` (12px). Uppercase micro-labels (section headers, badge
text) use a new `text-2xs` (11px) token, which exists only for caps, where the letterforms carry
legibility that 11px lowercase would not.

The nav-link size was left open by the token pass and closed with the nav work — see #17.

**12. No dark mode and no reduced-motion guard.** ✅ **Fixed 2026-07-26 (token pass).**

Dark mode is a full second palette under `prefers-color-scheme: dark`, not an inversion: surfaces
are warm near-blacks (never `#000`, which flattens depth), the accent lightens to `#a78be0` so it
still reads as the same purple against a dark field, and every status pair is retuned rather than
reused. `color-scheme` is declared in both, so form controls and scrollbars follow.

The tokens deliberately live in plain `:root` rather than `@theme`. A non-inline `@theme` block
holds static values only and cannot be re-pointed by a media query, and switching to `@theme inline`
would stop Tailwind emitting the `--color-*` variables at all, breaking every `var(--color-x)` call
site in the app. `@theme` keeps only what is genuinely static: the radius steps and `text-2xs`.

Reduced motion collapses animation entirely rather than substituting a gentler variant — nothing in
this app conveys meaning through motion alone.

## P2 — interaction and content

**13. Four always-on 44px buttons per task row.** ✅ **Fixed 2026-07-26**, but not as this audit proposed. The original plan was to reveal edit and delete on hover; the ui-ux-pro-max verification pass flagged "Hover vs Tap" as a High-severity rule, and hiding a destructive action behind hover makes it undiscoverable on touch. They are dimmed to 60% instead and come to full opacity on `group-hover` or `group-focus-within` — same discoverability, less competition with the title.

**14. Subtask rows are indented by a 44px button plus `ml-7`.** ✅ **Fixed 2026-07-26.** Indent is now exactly one control width, so subtask toggles align under the parent's complete button. A first attempt narrowed the toggle to 28px to tighten the rhythm and broke the 44px touch minimum; the existing Phase 04 test caught it and it was reverted.

**15. New-task subtask rows are unusable on mobile.** ✅ **Fixed 2026-07-26.** Rows stack below `sm` and keep the single-row layout above it.

**16. Destructive workspace leave is hover-only and unconfirmed.** ✅ **Fixed 2026-07-26.** State and action are separate controls, and leaving goes through `ConfirmDialog` — the task-delete dialog generalised.

**17. Top nav has no active state.** ✅ **Fixed 2026-07-26.** `NavLinks` highlights the current section and sets `aria-current`, so the cue is not colour-only. Nav type moved to 14px, closing the remainder of #11.

**18. Updates list has no empty state, no scroll affordance, and absolute timestamps.** ✅ **Fixed 2026-07-26.** Relative timestamps inside `<time dateTime>` for the first day then absolute; auto-scroll to the newest entry; empty states on both lists. `formatUpdateTime` is exported and unit-tested.

**19. Double-reported errors on workspace create.** ✅ **Fixed 2026-07-26.** Inline only, matching the task modals.

**20. Dead animation code.** ✅ **Fixed 2026-07-26.** Both the staggered `animationDelay` wrapper and `animationFillMode` are gone.

**21. Small correctness nits.** ✅ **Fixed 2026-07-26.** All `vh` units are `dvh`, the completed-section toggle has `aria-expanded`, and `/profile` has a skeleton matching its real layout.

## Not found (things that are already right)

Touch targets are 44px throughout, `aria-label`s are present on every icon-only button, the toaster
has correct polite/assertive live regions, `/tasks` has both `loading.tsx` and `error.tsx`, inline
form errors carry `role="alert"`, and the drag handle keeps a keyboard path. Phase 04 did its job;
what is left is visual system work, not accessibility rescue.

## What re-running the rules before implementing actually caught

Worth recording, because it changed the work rather than confirming it:

- **"Hover vs Tap" (High)** killed the plan to hover-reveal a task row's edit and delete controls.
  Hover does not exist on touch, and a destructive action hidden behind it is undiscoverable.
  De-emphasis achieved the same visual goal without the tradeoff.
- The same rule identified the workspace **Joined → Leave** hover swap as the identical
  anti-pattern already shipped, which the original audit had filed as a lesser concern (#16) rather
  than the touch-breaking bug it is.
- **"Confirmation Dialogs" (High)** made the case that leaving a workspace deserves at least the
  confirmation deleting a task already had, since it affects shared data.

field, a focus outline that collides with a rounded corner, the stacked subtask-row layout at

same session as the deferred Phase 06 browser checks.
